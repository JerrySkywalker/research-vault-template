# Mathematical knowledge notes

Use an existing [concept](../templates/concept.md), [method](../templates/method.md), or [literature](../templates/literature.md) note. Choose the form according to the note's purpose. Mathematics and formal references are optional. The Vault can be read and validated with no Lean installation, running Mathlib build, mounted project repository, or network connection.

## What to record

- Explain the question, the reusable mathematical idea, and its scope in plain language. Give the statement, relevant definitions and assumptions, a source locator, and the conditions under which a project can apply it.
- When a formal reference matters, record the origin repository or stable identity, full Git commit, repository-relative path and fully qualified declaration. Link to that exact source revision where access permits. Preserve the source attribution and note any adaptation. Use a safe logical identity for private sources and omit confidential details from public notes.
- Track proof verification and review of the note's meaning as distinct facts. Attribute a verification result to the originating evidence, relevant version and exact statement when those facts are known. If the source or evidence is unavailable, record the gap and leave verification unconfirmed. Keep enough plain-language context for offline reading. A reachable source link establishes access to the source, while an evidence record documents what was verified.
- Keep the existing bibliographic fields for literature notes. Use a citekey, Zotero item key, DOI or URL only when available, according to the [bibliography contract](INTEGRATIONS.md#bibliography). Leave attachments with Zotero.

## Review and promotion

Semantic promotion is a [reviewed Vault change](PROMOTION_WORKFLOW.md). Review terminology, hypotheses of the mathematical statement, applicability and provenance before admitting a cross-project interpretation. Formal promotion is a separate review by the Lab or a reusable library's maintainers. It governs proof source, statement compatibility, and licensing. Retain the original Lab evidence and link any external package at an exact revision. A proof check supplies a narrowly scoped observation for review. The originating Lab retains its evidence and decision records, and its library or the external package retains its executable proof. References and promotions are explicit Git changes and cause no synchronization.

Preserve existing notes and modes during [safe upgrades](UPGRADE.md). Bring this guidance over as a reviewed template delta if useful. Adapt a specialized README without replacing its identity.

### Induction on a finite sum

**Purpose.** Derive a closed form for a sum over the indices $0$ through $n-1$. Here the term at index $i$ is $2i+1$, and the target sum is $n^2$.

**Procedure and assumptions.** Work over natural numbers, with $n=0$ giving the empty sum $0$. Extending the range from $n$ to $n+1$ adds the term $2n+1$, which takes $n^2$ to $(n+1)^2$. The general formal step assumes an additive commutative monoid and a sequence indexed by natural numbers.

**Limitations and evidence.** The method applies to this finite, zero-based indexing convention. A different starting value changes the recurrence. The upstream declaration documents the general step. Its source locator was inspected for this example. Proof verification by this Vault is unconfirmed, and the illustrative note awaits semantic review if reused in an instance.

**Connections and provenance.** The upstream declaration is `Finset.sum_range_succ` in `leanprover-community/mathlib4` at `fc4f59e577feb1a4956671bc04ac18aaaf8cd842` (Mathlib v4.36.0), path `Mathlib/Algebra/BigOperators/Group/Finset/Basic.lean`. Its additive form is generated by `@[to_additive]` from the [pinned source](https://github.com/leanprover-community/mathlib4/blob/fc4f59e577feb1a4956671bc04ac18aaaf8cd842/Mathlib/Algebra/BigOperators/Group/Finset/Basic.lean#L559-L562).
